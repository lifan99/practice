# P1：可追溯问答基线

中心问题：能否用自己的组件，完成一次可解释、可重现的文档问答？前置为 RAG C1–C4、C6–C7；加入 C5 做词法对照。不等待进阶框架章节。

## 需求与边界

选择一个具体使用场景，写清使用者、文档范围、三种常见任务与无法承诺的能力。使用自己编写、获许可或适用许可允许使用的中文 Markdown 文档，记录来源和版本。课程的三份短样本只用于连通性检查。

自行设计命令行入口，支持导入、查询和运行评估；参数、退出码、输出格式与错误行为由你先写契约。核心检索使用自己的 C2–C5 实现；生成通过依赖接口接入，模型可以本地运行或使用服务。自定义接口不得改变原组件题的契约。

每个答案返回可核对的证据：文档身份、语料版本、来源、原文起止位置与引用文本。保留原文，引用须满足版本原文切片一致。不同切分方案的 chunk ID 不应被直接当作固定评估标签。

没有检索到证据时明确拒答，生成依赖不调用；有检索结果仍可能不足以支持答案，要在质量评估中记录，不能把“非空结果”当作充分证据。模型故障单独报告，不与无答案混在一起。生成内容不得假装已验证事实。

## 数据与首轮实验

自行建立至少20条**业务查询**作为课程练习规模；覆盖精确词、改写、多证据、歧义、无答案五类，每类至少2条，可在剩余样本中扩充。它们不是面试问题。来源／许可与不含敏感数据的说明随语料记录。

在调参前划分开发集与保留集，记录题目身份与所属类别；同一事实的近重复改写应分组划分。第一版可以只报告开发集；保留集到 P3 冻结方案后再使用。小样本只支持本练习中的观察，不用于市场或业务总体推断。

证据标签存为文档身份、版本、原文区间与相关等级，说明映射到当前 chunks 的规则。分别运行精确向量与 BM25，按同一查询集报告 Recall、MRR、NDCG；无答案组另评拒答，歧义组记录需要澄清的依据。接真实模型或本地生成模型后，人工核对答案正确性、证据支持与引用。只用固定回复时真实质量标为未评估，不填写准确率。

模型输入不得包含参考答案或人工相关性标签。记录版本、参数、调用次数、可得的 token／费用和硬件。具体口径沿用 [RAG 实验规范](../../rag_practice/core/experiments/README.md)。

## 公开验收矩阵

| 场景 | 必须可观察的行为 | 证据 |
| --- | --- | --- |
| 同一冻结语料重复导入 | 文档与块数不意外增长，引用身份稳定 | 导入统计与测试 |
| 中文、空白正文、重叠切分 | 原文区间一致，空白处理符合契约 | 边界用例与切片断言 |
| 检索无命中 | 明确拒答，不调用生成依赖 | 调用探针与输出 |
| 模型不可用 | 返回可区分的依赖故障，不伪造答案 | 受控故障测试 |
| 相同配置重新运行 | 检索评估可复现；生成随机性与差异有记录 | 命令、配置与结果文件 |
| 证据已取回但回答错误 | 能人工识别并归类，不能只看来源列表 | 脱敏案例与评审说明 |

## 交付与复审

提交运行说明、独立设计的代码与测试、数据说明、开发集评估及失败样本。解释 Top-k 与索引构建的时间／空间复杂度，并列出一个当前实现的容量限制。

公开测试通过后，自行变更一个输入条件检查迁移能力，或完成 [T1](../../curriculum/transfer/01_retrieval.md)。评审先看引用与错误行为，再看检索指标。P1 离线流程通过后可以开始 P2；尚未接真实模型的质量项继续保持未测，并在 P3 补齐。
