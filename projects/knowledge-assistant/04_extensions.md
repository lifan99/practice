# P4：按业务选择一个专题

前置为 P2、P3。中心问题：新增机制解决了哪个已观察到的问题？从下列方向选一条即可；先写需求、基线和预期，再学习相关框架章节。专题任务没有预置实现与自动验收器。

## A：可暂停、可恢复的工作流

适合需要人工审批或多阶段恢复的任务。先完成 LangGraph L1–L3、L6–L8 与 [T3](../../curriculum/transfer/03_recovery.md)。在本地模拟“检索依据→准备工单→人工批准／拒绝→创建工单”，明确状态、预算、终止与审计记录。

必须展示两个用户的任务隔离、拒绝无副作用、暂停后进程重启、业务动作提交后回执丢失与重复恢复。实际使用持久化 checkpointer，外部操作通过独立的本地模拟服务；不发送真实消息。评审业务操作身份、幂等约束与故障窗口。若加入改写检索循环，另对照无循环基线评估质量和额外调用，不把节点数当成收益。

## B：通过 MCP 暴露工具

适合需要把已有能力接入工具生态的任务。先完成 MCP L1–L4；使用 HTTP 再学 L5，文件资源再学 L8，框架适配再学 L9。暴露有 schema 的受限检索工具和一种来源资源，保留身份与版本约束；客户端不能借工具参数冒充其他用户。

使用真实 SDK client/server 协议往返验证能力发现、成功／失败、非法输入、依赖超时、取消与释放；同时用项目数据核对引用和越权行为。传输测试通过与真实宿主接入分别记录。若演示真实模型工具选择，再记录成功、选错工具与无工具调用案例。未接真实模型时只报告工具协议连通。

## C：关系与多跳检索

适合明确存在实体关系问题的语料。先完成 GraphRAG 两级。建立含来源与版本的事实图；人工事实允许，但必须标记，不能描述为已完成自动抽取。

固定一组关系任务与普通文档任务，比较向量／词法基线和图检索；至少覆盖实体歧义、环、重复事实、无支持路径、更新／删除与多跳证据。每个关系结论回溯原文，不能凭路径连通自动推出语义事实。报告构建／维护成本、是否改善目标任务及在哪些任务无收益。

## 共同完成标准

交出可复现演示、对应失败测试、与基础方案的对照、运行预算和已知限制。未测行为明确标记；新增框架若不能说明可观察的价值，可以撤回并保留结论。高级模型训练、分布式部署、完整 GraphRAG 全局检索不属于本阶段必修。
