# P3：以证据决定优化

中心问题：改动是否改善目标任务，代价是否可接受？前置为 P2、P1 的数据与基线。按失败归因选一项 C8 融合、C9 重排／预算或 C10 多查询；不要把三项全部实现作为进入实验的前置。其他方案也可，但先写清可检验假设。

使用[Milvus 主线](milvus.md)时，先保留 FLAT／COSINE 精确基线。需要优化检索规模或延迟时，可将 ANN 索引及其参数作为单项实验；固定向量和合格候选范围，对照精确结果测 ANN 召回，并记录构建、内存与写入开销。不同时更换 embedding 和索引来归因性能变化。

## 试验前固定

固定语料版本、证据标签、开发／保留集、模型与分词器、k、调用预算、随机性及计时环境。按用户任务声明目标和可接受退化，例如在固定调用上限下改善改写查询的召回，同时报告增加的延迟与费用；门槛由你在看结果前设定，不倒推有利阈值。

完成 F4 的真实模型接入要求：可使用本地开源模型与 embedding，不要求付费。受资源限制无法完成时，交付确定性实验与未测清单，本阶段的真实质量项保持未验收。

## 对比与消融

先复现 P1 的向量／BM25 基线，再在开发集上只改变一个主要因素。至少比较基线、选定改进和移除该改进后的配置。报告候选数、检索／模型调用次数、上下文长度、p50／p95、可得 token 与费用、失败数量。方法差异带来的额外调用必须计入，不混作同成本比较。

检索指标按 chunk 计算，切分变化后从稳定的版本原文区间重新映射标签。真实答案评估说明口径与分母，分别记录正确性、证据支持、引用准确性、有答案误拒与无答案误答；歧义样本单列。人工标注允许不确定和争议项，保留复核结果；自动裁判只是附加证据，不能用同一个模型自评替代全部核对。

冻结最终配置后才运行保留集并报告结果；若根据结果继续修改，该集合已参与开发，需要另留新数据用于后续最终评估。至少20条是课程练习规模，小样本差异不能声称普遍显著。重复试验记录次数和波动，不用单次最快值代表延迟。

## 失败与回归

每种情况建立一个可复现案例：未召回证据、证据排名过低、证据正确但答案错误、无答案误答，以及文档中夹带试图改变行为的指令。用合成指令检查能否越过身份边界或污染答案；少量样例通过不证明全面防注入。

将确认的确定性缺陷加入回归测试；模型质量回归使用冻结配置与单独运行入口，明确随机性、费用和人工复核范围。普通单元测试不应因联网或真实模型波动而不稳定。无法重现的失败应如实记录。

## 公开验收矩阵

| 项目 | 验收证据 |
| --- | --- |
| 基线可重现 | 固定版本、命令、参数和原始结果 |
| 改动有明确假设 | 试验前目标、单因素配置与消融 |
| 质量口径可信 | 文档版本与标签映射、分组分母、人工复核与争议项 |
| 成本与延迟可核查 | 实际调用日志、预热与重复次数、硬件及统计方式 |
| 未使用保留集调参 | 数据使用记录、最终配置冻结点与保留集报告 |
| 无提升或退化可解释 | 失败案例、取舍以及保留／撤回改动的决定 |

使用 [评估报告模板](../templates/evaluation.md)。学习成果包括证明某项优化在当前条件下不值得采用；不要求结果必须提升。完成后整理 [项目交付](../templates/delivery.md)，按岗位需要选 [P4](04_extensions.md)。
