# 项目主线：可追溯的中文知识库助手

把同一个业务场景逐步从命令行程序迭代为可交付服务。目标使用者需要在有权使用的中文文档中查证事实，并看到答案依据、文档版本和无法回答的边界。可以替换为自己的合法场景，但需保留各阶段要求和评估证据。

这些是独立作业规格，提供行为要求、公开场景与评审矩阵；**尚无项目实现、答案、预置自动测试或可直接启动的服务**。学习者自行设计、实现和测试。课程现有 CI 通过只表示练习环境正常。

## 可复用的 MVP 材料

[基础读物](../curriculum/readings/README.md)与[离线示例](../support/mvp_examples/README.md)已接入审核 MVP 的通用内容，主要支持 P1 的契约／依赖边界和 P2 的并发／服务生命周期。复用来源与哈希见[记录](../curriculum/readings/SOURCES.md)。示例是提供好的观察材料；项目服务和独立作业仍需自己设计，原 MVP 未提供的数据库、身份与持久化幂等不能标为已复用完成。

## 实现与成果放哪里

建议将项目实现放在单独的项目目录或仓库，用自己的包结构、测试和锁文件维护；本练习仓库只保存课程任务。复用已完成的核心机制时明确来源与版本，不通过修改练习契约适配服务。项目环境单独锁定，FastAPI、数据库驱动、容器工具和持久化 checkpointer 尚未包含在本课程锁文件内。

先用 [项目简报](templates/brief.md)界定用户、范围与约束，按阶段独立设计。个人学习记录继续放本地 notes/。学习者答案、个人记录、原始业务数据与报告不自动上传；公开展示使用合成或明确可公开的数据并逐项检查发布清单。禁止发布面试资料的规则继续适用。

## 评审方式

每阶段先提交契约、再给运行证据；按公开矩阵逐条标为通过、失败或未测，关联命令、测试和产物。自动测试、人工标注、受控故障与真实模型效果分别呈现。出现失败后针对具体原因修订并复测，接受满足契约的不同方案。

不预设统一准确率、QPS 或“生产级”标签。性能目标由你在试验前根据场景、硬件与预算声明；达不到时如实记录。P1–P3 完成的证据包括他人可复现的启动、一次用户任务、一次故障恢复和一次优化取舍，使用 [交付模板](templates/delivery.md)。
