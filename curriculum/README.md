# 从独立实现到项目交付

目标：面向 AI 应用开发／偏后端岗位，能够独立实现核心机制、设计接口、评估质量并交付可复现服务。课程不要求先完成所有框架章节。算法研究、模型训练与推理优化岗位需要另补对应训练。

本目录定义学习顺序；各主题 README 提供练习入口；[项目任务](../projects/README.md)定义阶段交付。所有新增项目和迁移任务都是独立作业规格，尚无参考实现或统一自动验收器。现有 pytest 只覆盖原来的组件练习。

先读[基础读物](readings/README.md)，按当前缺口选择契约、异步、HTTP 或服务边界，再完成对应补学任务。读物从审核 MVP 改编，配有无需第三方依赖的可运行示例；仍未覆盖的 SQL、容器和模型原理讲义在入口中明确列出。

## 主修路线

| 阶段 | 中心问题与先修 | 学习／活动 | 可观察成果与进入下一阶段的证据 |
| --- | --- | --- | --- |
| 1 · 机制与第一版系统 | 怎样从原文得到可追溯证据？Python、dataclass；向量和对数按需补 | RAG C1–C4、C6–C7；完成 P1 时加入 C5 作为词法基线 | [P1](../projects/knowledge-assistant/01_baseline.md)：自行串联的命令行程序、证据标签、首份评估；能说明复杂度和一次失败 |
| 2 · 工程化 | 怎样让另一位使用者可靠地调用它？HTTP、SQL、资源管理 | [基础补学](foundations/README.md) F2–F4；按需学习 LangChain 消息／适配与异步；完成迁移 T1、T2 | [P2](../projects/knowledge-assistant/02_service.md)：文档更新删除、身份隔离、重启后可用、容器启动与故障测试 |
| 3 · 有证据的优化 | 哪个瓶颈值得改？先固定 P1 基线与调参集 | 按失败归因选择 C8、C9 或 C10；保留无效优化的证据 | [P3](../projects/knowledge-assistant/03_evaluation.md)：同一评估口径下的质量、成本、延迟与消融报告 |
| 4 · 岗位专题选修 | 业务是否需要暂停审批、工具或关系查询？先完成 P2、P3 | 从 LangGraph、MCP、GraphRAG 中选与场景有关的一条；恢复场景完成 T3 | [P4](../projects/knowledge-assistant/04_extensions.md)：有基线对照、边界和失败证据的扩展 |

阶段1先让 C1–C4、C6 能组成最小程序，再完成 C7 和 C5 的对照；不必等 C8–C10 才做第一次评估。只完成组件测试，阶段成果仍应标为“未验收”。项目采用独立环境，项目依赖与运行记录由学习者维护。

## 项目向量存储主线

P1 保留手写精确检索作为可解释的基线。进入 P2 后按[Milvus 接入任务](../projects/knowledge-assistant/milvus.md)分步完成 Standalone 服务：固定向量对照、权限与版本、实际持久化及重启。业务数据仍需关系数据库与 SQL 基础；应用负责声明跨组件一致性。

PyMilvus 和 Milvus 服务在独立项目环境中配置并锁定版本，不加入 core 的最小环境。先完成 C1–C4、C6–C7 和 P1，不把安装服务作为当前组件练习的前置。

## 框架练习的取舍

| 主题 | 默认优先内容 | 按项目需要补学 |
| --- | --- | --- |
| LangChain | L1–L2 消息／类型与工具；选用工具时学 L4–L6；服务阶段学 L8–L10 对应能力 | L3 组合、L7 会话记忆；没有相关需求时可延后 |
| RAG 的 LangChain 集成 | 需要接框架时先读 L1–L3 的类型与边界，再做 L9 桥接 | L1–L8 机制重复题可用迁移证据替代，规则见该路径 README |
| LangGraph | 选工作流方向时学 L1–L3、L6–L8；按依赖顺序完成 | L4–L5 并行、L9 子图、L10 观测按需求选择；使用流接口前仍需对应练习 |
| MCP | 选工具方向时学 L1–L4；HTTP 接入加 L5，文件服务加 L8 | 分页、执行控制、框架适配和多服务按需求选择 |
| GraphRAG | 关系查询方向选修两级，保留向量／词法基线 | 自动抽取、社区与全局检索作为后续研究，不是求职项目默认依赖 |

“按需”指能力仍需被证明：例如项目使用并发却跳过 L9，就要用 [T2](transfer/02_async.md) 和项目测试提供同等证据。没有使用某框架时，不要求为了章节覆盖而引入它。

## 练习如何逐步减少帮助

1. **契约练习**：使用现有骨架与公开测试；提交边界测试、解释和必要的复杂度分析。
2. **迁移任务**：完成 [T1 接口与数据变化](transfer/01_retrieval.md)、[T2 原生异步执行](transfer/02_async.md)，自行设计模块和测试，不使用给定函数骨架。
3. **项目决策**：以阶段需求为约束，自定接口和方案；提交需求、设计取舍、实测与复盘。首次进入涉及恢复的专题再做 [T3](transfer/03_recovery.md)。

每完成两三个相关组件，就尝试串联或迁移；出现先修缺口时只补对应基础。一次即刻复现不能代替独立迁移。经过其他学习活动后，用未练过的输入或需求再次检查同一能力，并保持任务难度可比。

## 评审与学习记录

使用 [学习证据模板](templates/learning-evidence.md)，区分独立完成、获得提示后完成、参考实现后复现与尚未评估。记录实际获得的 AI 帮助及验证方式；不据此推断整体能力。

评审顺序：行为正确性与边界 → 解释与迁移 → 复杂度／资源生命周期 → 评估证据 → 可维护性。替代实现满足已公布契约即可接受；先指出具体反例或缺失证据，再修订并复测。项目各阶段另有验收矩阵，不设未经测量的统一准确率或性能门槛。

个人记录默认放本地 notes/，项目实现和报告单独维护；提交练习答案、学习笔记或项目成果前逐项确认发布范围。面试资料始终遵守根目录发布规则。

## 求职展示的完成范围

完成 P1–P3 后，应能演示用户任务、重现一次故障、解释一次优化，以及让他人按说明启动项目。采用 [项目交付模板](../projects/templates/delivery.md)标出已测行为和已知限制；模板本身不算项目成果。不以课程章节数、测试数或框架数量描述项目效果。

本路线覆盖 AI 应用开发中的一部分能力。Python、SQL、数据结构、HTTP、操作系统与网络基础需要结合项目查缺补漏；模型训练、GPU 推理与前端深度按目标岗位另设路线。
