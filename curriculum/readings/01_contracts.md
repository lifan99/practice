# 契约、校验与可替换依赖

前置：函数、字典、异常。目标：解释“收到一个值”和“接受一个业务结果”之间有哪些检查，并用原文区间核对引用。材料改编自 [MVP 数据契约与协议示例](SOURCES.md)，不要求学习完整审核系统。

## 从一份模型回答开始

审核 MVP 的 Judge 返回文本。`{"verdict":"banana"}` 是非空字符串，也是合法 JSON；但它不符合该项目的结论枚举。即使它改成合法结论，也可能缺少字段，或给出与材料不符的解释。

这说明至少要区分四层：

| 层次 | 可以确定性检查什么 | 通过后仍未证明什么 |
| --- | --- | --- |
| 文本 | 是否是字符串、是否非空白 | 格式与含义 |
| JSON | 文本能否解析成约定的数据结构 | 字段、枚举、引用 |
| 业务契约 | 必填字段、类型、范围与字段关系 | 事实和推理正确 |
| 内容评估 | 结合证据人工或实验核对结论 | 没有实际核查的外部事实 |

契约应写清输入、输出、错误与失败后的状态。例如“模型输出非法时，不发布最终成功报告”比“解析异常时抛错”更完整；后者可能遗漏旧成功结果仍被保留的缺陷。

## 类型注解和数据容器的作用

`start: int` 表达类型意图，普通 Python 调用不会自动检查它。`@dataclass` 减少字段保存与构造的重复工作；`frozen=True` 限制字段重新赋值，但不会递归冻结字段中的列表，也不会验证字段的业务含义。

Pydantic 可以承担运行时字段校验，但是否进行类型转换、是否允许额外字段，需要按配置和实际版本验证。业务层仍需要自己的不变量；绕过 HTTP 直接调用业务函数时也应得到符合契约的行为。

Python 中 `bool` 属于 `int` 的类型体系。坐标契约若排除 bool，单独使用 `isinstance(value, int)` 不足以表达这个限制。你需要区分“按 Python 类型系统接受”与“业务允许”。

## 原文区间怎样成为可核查的引用

阅读并运行 [quotes.py](../../support/mvp_examples/quotes.py)：

```bash
python support/mvp_examples/quotes.py
```

示例中的原文为 `仅用内存保存记录，重启后历史仍在。`，引用 `重启后历史仍在` 对应 `[9,16)`。左端包含，右端不包含；先在原文上核对 `original[9:16]`，再读校验函数。

校验分别检查整数坐标、范围、非空引用与切片一致；它不能证明引用支持模型给出的结论。小函数假设调用者已提供所需字段，因此也不是完整的输入解析器。

位置按 Python 字符串的 Unicode 码点索引，不是 UTF-8 字节位置或屏幕字符宽度。改写换行、先 strip 原文、或把引用自动定位到第一次出现，都可能破坏引用身份。相同文本出现两次时，应以给定位置验证，不能擅自替模型修复为第一处。

RAG 的引用还需要文档身份与版本：同一位置只能相对于同一份原文解释。切分策略改变后，chunk ID 可能变化，稳定的原文区间标签需要重新映射。

## 依赖接口让测试控制什么

运行 [protocols.py](../../support/mvp_examples/protocols.py)：

```bash
python support/mvp_examples/protocols.py
```

`review` 只依赖 `complete(model=..., messages=...)`，同一入口分别接 FixedClient 和 EchoClient，输出为 `fixed response` 和 `hello`。业务函数无需知道如何联网，也无需为测试使用真实模型。

Protocol 描述兼容接口，默认不是运行时验证器；一个对象满足调用签名，不保证其结果符合业务契约。固定回复可以验证调用参数和数据流，却不能证明模型懂得任务。样例用同步接口解释依赖替换，实际异步客户端还需要 await 和清理，见[下一篇](02_async.md)。

## 怎样验证这一层

一个失败测试同时检查：坏输入、失败类别、依赖调用次数，以及是否留下错误的成功状态。请求在调用前非法时，应能观察到模型调用为0；非法报告被拒绝时，不能把未经校验的内容发布成成功报告。使用临时文件、快照与可控依赖区分输入被修改和正常输出。

标准库 JSON 解析也有自己的默认行为，例如重复键可能覆盖前值；需要严格拒绝时，应明确约定并测试，参考 [Python JSON 文档](https://docs.python.org/3.12/library/json.html)。这些规则应由业务需求决定，不能从一个示例推广为所有接口的要求。

独立完成 [F1](../foundations/01_contracts.md) 后，再把这些原则用于 RAG 的文档与引用契约。先解释一个通过格式校验仍然错误的结果，再记录自己新增的边界测试；不把读过 quotes.py 记作已独立实现完整校验层。
