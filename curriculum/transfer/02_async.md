# T2：独立设计有界异步批处理

前置：[F2](../foundations/02_async.md)。目标：用标准库 asyncio 自行设计批处理入口，证明能控制执行、失败、取消和资源；不得通过 LangChain abatch 或 MCP 批处理包装器完成本任务。不提供实现骨架或算法提示。

## 行为契约

- 接收有限输入序列、异步处理依赖、正整数并发上限和正的有限单项超时；bool 不算合法数字。先校验配置，有效空输入返回空结果且不调用依赖。
- 结果与输入位置一一对应，保留重复输入。普通 Exception 以可区分的逐项失败结果表示，不丢失其他成功项；超时单独标记。
- 同时执行的处理依赖不超过上限。有至少两个输入且上限大于1时，受控依赖必须能观测到交错执行。
- 单项超时从该项进入处理依赖时计起，不把排队时间混入；超时后等待该项清理完成，释放资源后才能当作完成。依赖约定可取消且清理最终会结束，超时不保证清理后总耗时严格小于该值。
- 调用者取消时，取消本批尚未完成的工作，等待本批创建的任务完成收尾，再向上层传播取消；不得返回一份伪成功结果。
- 不修改输入，不阻塞事件循环，不关闭调用者持有的客户端，不在入口内部调用 asyncio.run。

例如输入 `["a","b","a"]`，中间项失败时，结果仍有3个位置，首尾各对应自己的调用。结果类型和公开函数名由你定义，并先写契约。

## 验收证据

自行编写可控依赖与测试，覆盖空输入、配置非法、重复输入、单项失败、超时、调用者取消、进入依赖失败与清理。分别展示并发上限确实生效、允许交错、结果顺序稳定和取消后资源已释放；计时不能作为唯一并发证据。可用测试级保护超时避免测试挂住。

说明创建任务数量与输入规模的关系、峰值活动依赖数和内存开销。基本契约不要求处理无限输入；大规模流式输入和背压另作扩展。随后对照 [LangChain L9](../../langchain_practice/lessons/09_async.md)，解释框架代办了哪些工作，哪些生命周期责任仍在调用者。
