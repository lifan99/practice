# C2：窗口与段落，保留原文位置

本级把一份 `Document` 拆成可回溯到原文的 `Chunk` 列表。先完成 **A：重叠窗口**，单独验收后再做 **B：段落聚合**。两部分都使用普通 Python 字符串和本包数据结构，不调用现成 splitter，也不需要模型或向量数据库。

任务文件：[level02_chunking.py](../exercises/level02_chunking.py)。前置：字符串切片、列表、整数边界；B 还需要阅读正则表达式。本级直接接收内存中的 Document，不要求先调用 C1 读取文件。

## 1. Chunk 保存什么

使用已经提供的 [types.py](../types.py)，保留两个函数的签名，不重新定义数据类。

| 字段 | 含义 | 共同约定 |
| --- | --- | --- |
| `source` | 文档来源 | 原样保留 `document.source` |
| `start` | 当前块在原文中的起点 | 从0计数，包含该位置 |
| `end` | 当前块在原文中的终点 | 不包含该位置，且不超过原文长度 |
| `text` | 当前块正文 | 必须等于 `document.text[start:end]` |
| `chunk_id` | 来源与区间组成的标识 | 严格为 `source:start:end` |

例如 `Document(text="  中文\n", source="note.md")` 的区间 `[2,4)` 是 `中文`，对应 ID 为 `note.md:2:4`。原文中的空格仍占位置，不能先改写原文再套用旧坐标。

长度和偏移按 Python 字符串的 Unicode 码点计量，不是 UTF-8 字节或模型 token；`A😀中B` 的长度为4。两个函数均返回按 `start` 升序排列的 `list[Chunk]`，不产生空块，不修改输入文档，不在不同调用间共享结果列表。

重复正文可以出现在不同区间，必须保留各自位置和 ID；不能按正文去重，也不能总把位置指向第一次出现。

## A：重叠窗口

```python
def window_chunks(document: Document, size: int, overlap: int = 0) -> list[Chunk]:
    ...
```

### A1. 参数与输出契约

参数按整数输入；只校验以下取值范围：

- `size > 0`。
- `0 <= overlap < size`。
- 任一范围不满足时抛 `ValueError`；空文本也必须先校验参数。

有效参数下的输出应满足：

1. 空文本返回 `[]`；全空白文本仍按窗口切分。
2. 非空文本的第一个起点为0，相邻起点相距 `size - overlap`。
3. 单块长度最多为 size；最后一块可以较短，终点不能超过原文末尾。
4. 当前窗口已经覆盖原文末尾时就结束，不再额外返回完全包含在当前块中的尾块。
5. 每块直接对应原文连续区间，保留空格、制表符和换行；不清理块边缘。
6. 未传 overlap 时按0处理；相同输入和参数应得到相同结果。

### A2. 完整输出示例

输入：`Document("abcdefghij", "note.md")`，size=4，overlap=1。

| 顺序 | `[start,end)` | `text` | `chunk_id` |
| --- | --- | --- | --- |
| 1 | `[0,4)` | `abcd` | `note.md:0:4` |
| 2 | `[3,7)` | `defg` | `note.md:3:7` |
| 3 | `[6,10)` | `ghij` | `note.md:6:10` |

第三块已覆盖末尾，因此没有第四块 `[9,10)`。这里每对相邻块有1个字符重叠，输出中的重复字符是预期行为。

### A3. 边界示例

| 原文 | size / overlap | 预期区间 | 需要注意什么 |
| --- | --- | --- | --- |
| `abcd` | 4 / 1 | `(0,4)` | 长度恰好为 size，只返回一块 |
| `ab` | 4 / 3 | `(0,2)` | size 大于原文，即使 overlap 很大也不多切 |
| `abcdef` | 4 / 1 | `(0,4), (3,6)` | 最后一块不足 size |
| `abcdefgh` | 4 / 0 | `(0,4), (4,8)` | 无重叠，整除时没有空尾块 |
| `abcde` | 3 / 2 | `(0,3), (1,4), (2,5)` | overlap 可以等于 size-1 |
| `" \t\n"` | 2 / 0 | `(0,2), (2,3)` | 全空白正文仍切分 |
| `""` | 4 / 1 | `[]` | 有效参数下的空文本 |
| `""` | 0 / 0 | 抛 `ValueError` | 空输入不绕过参数校验 |

示例中的引号和转义用于显示实际空白，不属于正文。完成后解释：起点为什么会前进、切分为什么一定终止，以及重叠如何影响输出总字符数。

## B：段落聚合

```python
def paragraph_chunks(document: Document, max_chars: int) -> list[Chunk]:
    ...
```

### B1. 什么算一个段落

max_chars 按整数输入，必须大于0，否则抛 `ValueError`；空文本和全空白文本也先校验参数。

段落分隔符固定为正则表达式 `\n[ \t]*\n`，采用 Python 正则的非重叠匹配。它表示两个换行符之间只能有空格或制表符；单个换行符不分段。本级不要求 Markdown 标题、代码块或句子语义解析，也不额外改写换行形式。

每个分隔得到的片段去除首尾空白后，确定有效正文在**原文**中的区间。空白片段忽略。去除边缘空白只影响所选区间，不修改 Document；有效区间内部的空格和换行保持原样。

例如 `"  aa\n\nbb  "` 的两个有效段落是 `[2,4)` 的 `aa` 和 `[6,8)` 的 `bb`。单个换行也可能属于段落正文，例如 `"aa\nbb"` 是一个有效段落。

### B2. 聚合与超长段落契约

1. 按原文顺序考虑有效段落。一个段落能完整放入当前块时，应将其并入；不能任意提前结束仍能容纳下一段的块。
2. 合并后的长度是“首段有效起点到末段有效终点”的**完整原文区间长度**，包括中间的分隔符和空白。不能只累加各段正文长度。
3. 加入下一段会超出 max_chars 时，当前块结束，下一段从新块开始；不能跳过中间段落去拼后面的段落。
4. 有效段落自身超过 max_chars 时，将该段落独立切成无重叠连续块。除最后一块外，每块长度恰为 max_chars；最后一块可以较短。起止位置仍相对于整份原文。
5. 超长段落拆出的所有块都独立保留，包含较短的最后一块；它们不与前后段落合并，即使剩余长度看起来能容纳邻段。
6. 空文本或全空白文本返回 `[]`。每个输出块非空且长度不超过 max_chars，所有有效段落的正文字符都要保留。

合并会把两段之间原有的空白保留在同一块中；没有合并时，段落之间的分隔符可以不属于任何块。A 的窗口原样覆盖全文，B 按有效段落区间选择正文，两者的空白处理规则不同。

### B3. 合并时怎样计算预算

输入：`Document("  aa\n\nbb\n\ncccccc\n\nz  ", "note.md")`，max_chars=6。

| 顺序 | `[start,end)` | `text` | `chunk_id` |
| --- | --- | --- | --- |
| 1 | `[2,8)` | `aa\n\nbb` | `note.md:2:8` |
| 2 | `[10,16)` | `cccccc` | `note.md:10:16` |
| 3 | `[18,19)` | `z` | `note.md:18:19` |

第一块含4个正文字符和2个换行，共6个字符。若预算改为5，`aa` 与 `bb` 必须分开；不能为了合并而删除换行。

### B4. 超长段落的短尾块也独立保留

输入：`Document("a\n\n12345\n\nb", "note.md")`，max_chars=4。

| 顺序 | `[start,end)` | `text` |
| --- | --- | --- |
| 1 | `[0,1)` | `a` |
| 2 | `[3,7)` | `1234` |
| 3 | `[7,8)` | `5` |
| 4 | `[10,11)` | `b` |

虽然 `5\n\nb` 长度刚好为4，也不能把它们合并：`5` 是超长段落的尾块，必须独立保留。
