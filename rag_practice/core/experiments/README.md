# RAG 实验规范：从基线逐步比较

C1–C4、C6–C7 后就开始第一轮实验，P1 加入 C5 做词法对照；不等待 C8–C10。自行建立脚本与报告并保留命令，本页提供评估口径，不提供串联答案。可先离线验证机制，再接真实服务或本地模型；不要求付费调用。

阶段交付以 [P1 基线](../../../projects/knowledge-assistant/01_baseline.md)、[P3 评估优化](../../../projects/knowledge-assistant/03_evaluation.md)为准；本页不要求把所有优化都做完。使用[报告模板](../../../projects/templates/evaluation.md)记录，未接真实模型时语义质量保持未评估。

## 1. 固定数据与基线

使用 [现有语料](../../data)作为组件连通性起点，再加入自己有权使用的中文文档。三个短文档不足以证明真实质量。固定语料版本、embedding 名称／版本、分词器、切分参数、k 与随机种子（适用时）。

自行建立至少20条问题的练习集，这是本项目的练习规模要求，不是统计充分性的保证。包含精确关键词、自然语言改写、多证据、歧义、无答案五类。相关证据先标注为 `source + 原文[start,end)`，再映射当前切分的 chunk_id；不能在切分变化后继续使用旧 ID 标签。说明你的区间重叠标注规则，并人工复核。

独立保留用于调参和最终报告的问题；公开用例不要同时充当全部调参和最终评估数据。每题记录 grade 0–3，分开报告有答案与无答案问题；无答案问题另检查拒答行为，不能靠 Recall=0 区分正确拒答与错误拒答。

## 2. 组件与端到端实验

先比较精确向量与 BM25。后续根据失败归因，从 RRF、重排或多查询中选择一项做改进与消融；每次只改一个主要因素，使用相同问题和明确的调用预算。其他机制可继续作为选修，不要求凑齐全部配置。模型可以是真实 embedding／reranker，不要求自己训练。

基础闭环先自行串联原文→C2切分→C4或C5检索→C6生成。按需引入 C8 融合、C9 重排与上下文预算、C10 多查询；C6 通过受控 retrieve 回调接收选好的命中，策略不应隐藏在模型里。

计时说明预热、重复次数、硬件与是否含网络；小样本p95仅作为练习观察值。记录的调用次数与费用来自实际日志，不能凭框架名称估算。没有真实生成模型时，只能报告链路行为，不填写答案正确率。

真实生成实验另外人工评估答案正确性、证据支持、引用准确性与拒答；记录标注口径和争议样本。来源列表不证明引用真实支持结论。抽查至少三类失败：未找回证据、证据找回但排序靠后、证据正确但答案错误。

## 3. 框架替换

需要框架时完成 [LangChain 桥接](../../langchain/README.md)，在相同 chunks 和问题集上替换输入输出适配，先验证 ID、原文、偏移、来源和 query 的传递。再单独替换向量存储／模型，不同时改变多个组件；框架替换是按需实验。

手写索引与框架索引分数或同分顺序可能不同；使用无同分的样例对比排序，同时显式记录相似度、归一化和过滤规则。不要强制不具备相同语义的 raw score 数值相等。

报告最后回答：机制实现的复杂度、哪项优化有效／无效、成本变化、具体失败案例、哪些结果仍未测量。持久化、增量更新、权限与容器部署已纳入 [P2 项目任务](../../../projects/knowledge-assistant/02_service.md)，需自行实现并验收；HNSW／ANN 等容量专题按需求选修。
